# ANL MineOps 需求证据（2026-08）

这份记录区分“来源直接说了什么”和“项目据此做出的推断”，不把社区观点当作统计结论。

## 直接证据

- [MineBBS：个人对 MC 开服这 8 年的看法](https://www.minebbs.com/threads/mc.45281/)：讨论开服门槛降低后，服务器供给增加、内容同质化、玩家获取和长期留存变难。
- [MineBBS：Craft 梦想岛全岗位招募](https://www.minebbs.com/threads/craft.46121/)：同一个服务器项目同时需要运维、备份、部署、问题处理、玩法、客服、测试和宣传人员。
- [MineBBS：服务器崩溃](https://www.minebbs.com/threads/37160/)：出现区块数据损坏、磁盘健康和异地容灾备份讨论。
- [Reddit r/admincraft：How does everyone backup their servers?](https://www.reddit.com/r/admincraft/comments/qgeo2b/how_does_everyone_backup_their_servers/)：服主分享定时保存、归档、保留策略和 RCON 通知脚本，说明备份流程经常需要人工维护。
- [Endstone](https://github.com/EndstoneMC/endstone)：Bedrock Dedicated Server 软件，支持 Python/C++ 插件和 Windows/Linux。
- [Minecraft RCON MCP Server](https://github.com/MinecraftCodeFoundary/Minecraft-MCP-Server)、[ReyxGPT](https://github.com/chrismethsillo/reyxgpt)：已有项目集中在 RCON 命令、状态和日志接入。

## 工程推断

1. v1 先做“可解释的安全运维”，比直接做玩法生成或营销自动化更容易验证价值。
2. 不能把任意 RCON/控制台命令直接暴露给模型；工具必须有类型、策略、审批和审计。
3. Endstone 需要独立适配层，因为 BDS、日志、进程和可选 RCON 插件不是同一个接口。
4. 真实 BDS 不作为本地 CI 门槛，DemoAdapter 和固定 fixture 足以验证 Agent、权限、API 和 UI 主流程。
